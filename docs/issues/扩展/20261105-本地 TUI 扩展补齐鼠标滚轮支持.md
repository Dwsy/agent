# Issue: 本地 TUI 扩展补齐鼠标滚轮支持

## Goal

`~/.pi/agent/extensions/` 下所有自绘滚动/选择型 TUI 组件都能用鼠标滚轮操作，键盘路径不变。

## 背景/问题

pi-tui 在全屏模式把归一化鼠标事件派发给组件的 `handleMouse`，但本地扩展的自绘组件只实现了 `handleInput`；包装内置组件的 wrapper 也只转发 `handleInput`，导致滚轮事件落到渲染器兜底（滚 transcript）而不是滚 overlay 内容。`zz-system-prompt-history/PromptViewer` 已作为样板补齐。

## 验收标准 (Acceptance Criteria)

- [ ] WHEN 滚轮落在有滚动状态的 overlay 上，系统 SHALL 按 `wheelDelta` 滚动该 overlay 内容并双向 clamp
- [ ] WHEN 滚轮落在选择型列表上，系统 SHALL 移动选中项并保持滚动窗口同步
- [ ] WHERE 组件包装了内置组件，系统 SHALL 转发 `handleMouse` 给子组件
- [ ] IF 事件不是 wheel 或 `wheelDelta` 为空/为 0，THEN 系统 SHALL 返回 `undefined` 交回渲染器兜底
- [ ] 所有键盘滚动/选择行为保持不变

## 关键决策

| 决策 | 理由 |
|------|------|
| 只做 wheel，不做 click 命中测试 | 与键盘路径一一对应，避免为每个自绘布局引入行命中几何契约 |
| 不抽共享 util | 各扩展独立加载、包路径互不相同，共享模块会引入跨扩展依赖 |
| 双栏组件按指针 x / 当前焦点分流 | 与键盘 focus 语义一致，不改动渲染布局 |
| `tool-inspect` / `btw` / `style-selector` 去掉无用的 `Container` 继承 | 三者从不 `addChild`、都完全 override `render`；基类 `handleMouse` 返回 `TuiMouseDispatchResult`，与 `TuiMouseEventResult` 签名冲突（TS2416），去掉继承才能正确声明鼠标处理器 |
