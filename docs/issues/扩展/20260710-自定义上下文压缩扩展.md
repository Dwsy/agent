# Issue: 自定义上下文压缩扩展

## Goal

交付一个可自动发现的 Pi 扩展：用户可在 TUI 中选择 Pi 已配置模型与摘要算法，接管手动、阈值和 overflow 三种上下文压缩路径。

## 背景/问题

Pi 内置压缩固定使用当前会话模型与默认摘要算法。Pi 0.80.3 已公开 `session_before_compact` hook，可返回自定义 `CompactionResult` 覆盖默认行为；本任务以该稳定 API 实现，不修改 Pi 运行时。

## 验收标准 (Acceptance Criteria)

- [x] WHEN 用户执行 `/compaction`，系统 SHALL 打开可键盘操作的 TUI 配置面板，并显示启用状态、模型、算法和摘要预算。
- [x] WHEN 用户保存配置，系统 SHALL 原子写入 `~/.pi/agent/extensions/pi-custom-compaction/config.json` 并立即应用。
- [x] WHERE Pi 已配置模型可用，系统 SHALL 允许从 `ctx.modelRegistry.getAvailable()` 中选择压缩模型。
- [x] WHEN Pi 触发手动、阈值或 overflow 压缩，系统 SHALL 使用已配置模型与算法返回有效 `CompactionResult`。
- [x] IF 配置模型不存在、无认证、模型请求失败或返回空摘要，THEN 系统 SHALL 通知原因并回退 Pi 内置压缩。
- [x] WHERE 算法为 `pi-default`，系统 SHALL 复用 Pi 导出的 `compact()`，保留默认切点、split-turn 和文件操作追踪。
- [x] WHERE 算法为 `structured`，系统 SHALL 生成含目标、决策、改动、当前状态、风险与下一步的 Markdown 摘要。
- [x] WHEN 处于 print/JSON/RPC 等无直接 TUI 模式，系统 SHALL 不依赖自定义组件，压缩逻辑仍可执行。
- [x] 代码 SHALL 通过类型检查、单元测试和 Pi 扩展加载验证。

## 关键决策

| 决策 | 理由 |
|------|------|
| 使用 `session_before_compact` | 覆盖 manual、threshold、overflow，且无需 patch AgentSession。 |
| 配置模型仅来自 `modelRegistry.getAvailable()` | 复用 Pi 的 provider、OAuth、API key 和 models.json，避免复制认证逻辑。 |
| `pi-default` 复用 `compact()` | 保留 Pi 已验证的切点、split-turn 和文件追踪。 |
| `structured` 为首个自定义算法 | 针对编码会话稳定保留继续工作所需的关键信息。 |
| `role-persona-old` 让出 compaction owner | 避免其记忆提取摘要覆盖用户配置的最终 `CompactionResult`。 |

## Notes

- `session_before_compact` 多扩展同时返回时，以最后一个非空返回值为准。
- `event.signal` 已传入算法调用以支持用户取消与 overflow recovery。
- role/persona 的 `before_agent_start` 注入不进入压缩模型请求；`structured` 显式排除持久角色规则，避免重复进入 checkpoint。
- TUI follow-up: panel now renders a full box border; model search is fuzzy and model rows show output price only; status widget defaults to off.
- 记忆交接 follow-up: custom compaction 通过 `role-persona-old.compaction-memory-handoff` 注入、解析和持久化 `<memory>`；role 扩展不再返回竞争结果。
- 文件追踪 follow-up: 两种算法都在 checkpoint 末尾写入 Pi 兼容的 `<read-files>` / `<modified-files>` 标签，并从前一份 checkpoint 合并累计结果。
