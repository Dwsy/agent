# Issue: 完善 role-persona-old 角色配置弹窗

## Goal

让无参数 `/role` 打开统一 TUI 控制中心，可完成角色管理、全量插件配置，并查看当前角色实际注入的角色定义与记忆块。

## 背景/问题

原 `/role` 仅提供分散的子命令与文本状态，无法集中配置记忆系统，也无法确认当前 system prompt 实际包含哪些角色和记忆定义。

## 验收标准 (Acceptance Criteria)

- [x] WHEN 在 TUI 中执行无参数 `/role`，系统 SHALL 直接渲染自定义键盘导航 overlay，不先进入系统 `select`。
- [x] WHERE 角色控制中心，系统 SHALL 支持状态、映射/切换、创建、默认角色、目录禁用和记忆查看。
- [x] WHEN 编辑插件配置，系统 SHALL 覆盖全部配置分组并按字段合并持久化，不覆盖其他字段。
- [x] IF 环境变量与配置文件冲突，THEN 系统 SHALL 继续以环境变量为最高优先级。
- [x] WHEN 查看注入预览，系统 SHALL 展示可确定的 core prompt、高优先级、长期和 daily memory，并明确标记查询相关动态召回。
- [x] IF 预览动态召回规则，THEN 系统 SHALL 不执行搜索、强化、pending 晋升或外部请求。
- [x] WHERE 非 TUI/RPC 模式，系统 SHALL 保留原有 `/role info|create|map|unmap|list` 兼容入口。

## 关键决策

| 决策 | 理由 |
|------|------|
| 无参数 `/role` 直接打开自定义 overlay，保留现有子命令 | 首屏即可展示角色状态与操作，不依赖系统 `select`，同时不破坏脚本/RPC 兼容性 |
| 配置按字段 patch 写入，而非写回完整有效配置 | 避免把默认值或环境变量覆盖固化进用户文件 |
| 注入预览不执行查询相关召回 | 避免预览导致记忆强化、pending 晋升或外部副作用 |
| 部分设置提示 `/reload` 或重启 | `index.ts` 中部分配置在扩展初始化时缓存为常量 |
