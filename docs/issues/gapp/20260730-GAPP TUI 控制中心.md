# Issue: GAPP TUI 应用渲染器

> 文件名保留早期“控制中心”命名以避免移动历史链接；最终实现不是控制中心。

## Goal

让 TUI 成为 GAPP 的正式应用渲染器。GAPP 可在 bundle 中提供 `tui.mjs`，该模块返回一个 `pi-tui` Component；独立 CLI 与 Pi 直接挂载这个应用组件，并与 WebView renderer 共享 `state.json` 和领域工具。

## 架构纠正

最初错误地把需求实现成 Overview / State / Tools 管理面板。用户澄清后，该方案被废弃：TUI 不负责浏览元数据或手工调用任意工具，而是运行 GAPP 自己的界面和交互逻辑。

最终边界：

```text
GAPP bundle
  meta.json + state.json + tools.json
  ├─ index.html   → WebView renderer（可选运行路径）
  └─ tui.mjs      → TUI app renderer
                    ├─ standalone TUI + ProcessTerminal
                    └─ Pi ctx.ui.custom()
```

## 验收标准

- [x] GAPP 可通过 bundle 根目录的 `tui.mjs` 定义自己的 TUI Component。
- [x] `gapp-tui [id] --cwd <project>` 直接渲染应用，而不是控制中心。
- [x] Pi `/gapp tui [id]` 与 `/gapp-tui [id]` 挂载同一个应用 renderer。
- [x] TUI 应用 runtime 提供状态读取、工具调用、刷新、输入请求、主题、按键和宽度辅助。
- [x] TUI 工具调用不会自动打开 WebView（`openIfNeeded: false`）。
- [x] 省略 id 时只列出提供 `tui.mjs` 的 GAPP。
- [x] Demo Kanban 在终端直接渲染三列/窄屏看板，并支持导航、新增、移动、指派、优先级、删除和改标题。
- [x] TUI 与 WebView/agent 共享 `state.json`、`tools.json` 和 `invokeGappTool()`。
- [x] 现有裸 `/gapp` 生命周期列表与 `/gapp open` WebView 行为不回归。

## 实施结果

### Renderer runtime

- `gapp/tui.ts`
  - 约定入口 `tui.mjs`。
  - 动态加载 `default` 或 `createGappTui(runtime)`。
  - 校验并包装 Component，保证终端宽度安全。
  - 提供 `getState`、`call`、`refresh`、`prompt`、palette、key、pad/truncate、close。
  - 应用本地导航输入后主动请求重绘。

### Hosts

- `gapp/cli.ts`：`ProcessTerminal` 直接挂载应用 Component，prompt 临时切到 `Input`。
- `gapp/tui-pi.ts`：`ctx.ui.custom()` 直接挂载相同 Component，prompt 使用 Pi editor。
- `commands.ts`：`/gapp tui` 与 `/gapp-tui` 改成应用渲染语义。

### Shared operations

- `gapp/service.ts` 继续统一 disk `stateOps`、Host 与 live handler 调用。
- `runtime-host.ts` 与 `runtime-pi.ts` 只负责运行环境差异。
- agent `gapp_call` 复用同一 service。

### Demo

- `.pi/gapp/demo-kanban/tui.mjs`：应用拥有的看板 renderer。
- 宽屏并排三列，窄屏单列。
- 所有交互调用现有 `tools.json`，状态写回同一 `state.json`。
- `index.html` 可继续作为同一 GAPP 的 WebView renderer，但不是 TUI 的实现或依赖。

## 关键决策

| 决策 | 理由 |
|------|------|
| 应用拥有 `tui.mjs` | 通用宿主无法从任意 HTML 推导应用交互；renderer 必须表达领域 UI |
| 模块不直接 import `pi-tui` | GAPP bundle 不需要自己的 node_modules，独立与 Pi 解析一致 |
| 返回结构化 Component | 仍使用 `pi-tui` 的渲染和输入协议，而不是自建第二套终端框架 |
| runtime 注入 prompt/call/state/palette | 应用代码保持宿主无关，Pi 与 standalone 只实现边界适配 |
| `index.html` 与 `tui.mjs` 可共存 | 同一应用可有多种 renderer，但共享状态与领域工具 |
| TUI call 禁止自动开 WebView | 终端应用不应因执行操作产生浏览器副作用 |

## 范围外

- 把任意 HTML 自动翻译成终端 UI。
- 在 TUI 内嵌浏览器或 WebView。
- 新增第二份状态存储或第二套领域工具协议。
- 通用声明式终端 UI DSL；当前使用应用拥有的 JavaScript Component module。
