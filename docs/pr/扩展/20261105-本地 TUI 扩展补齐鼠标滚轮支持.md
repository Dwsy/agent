# 本地 TUI 扩展补齐鼠标滚轮支持

> 让本地自绘 TUI 组件接收 pi-tui 的归一化滚轮事件，键盘路径保持不变。

## 背景与目的 (Why)

pi-tui 仅在 fullscreen(alt-screen) 模式把归一化鼠标事件派发给 `Component.handleMouse`。本地扩展的自绘组件只实现 `handleInput`；包装内置组件的 wrapper 也只转发键盘，导致滚轮落到渲染器兜底（滚 transcript）而不是滚 overlay 内容。

## 变更内容概述 (What)

- 21 个扩展文件补齐 `handleMouse`，三类模式：
  - **自绘滚动/选择**：按 `wheelDelta` 改 `scrollOffset` / `selectedIndex`，双向 clamp，返回 `{ handled: true }`
  - **双栏**：按 `event.x` 分流（列表选择 vs 详情滚动），`splitX` 由 render 时的分栏几何记录
  - **wrapper 转发**：把 `handleMouse` 转给内置 `Container` / `SelectList` / `SettingsList` / `Input` / `Editor` / 子组件
- 非 wheel、`wheelDelta` 为空或 0 时返回 `undefined`，交回渲染器兜底
- 只做 wheel，不做 click 命中测试；不抽共享 util（各扩展独立加载）
- `tool-inspect`、`btw`、`style-selector` 去掉未使用的 `Container` 继承：三者从不 `addChild`、都完全 override `render`，而基类 `handleMouse` 返回 `TuiMouseDispatchResult`，与 `TuiMouseEventResult` 签名冲突（TS2416）

## 风险与影响评估 (Risk Assessment)

| 轴 | 影响 |
|---|---|
| UX | 全屏模式滚轮现在滚 overlay 内容；regular 模式行为不变（终端接管鼠标）；键盘路径不变 |
| DX | 每个组件多一个短方法；无共享抽象，重复但局部、易 grep |
| Agent 可读性 | `handleMouse` 与 `handleInput` 一一对应，契约测试锁定"每个键盘 handler 都有匹配的鼠标 handler" |

风险点：三个组件去掉 `Container` 继承。已用 ToolListComponent 真实实例 smoke test 验证 render + wheel 正常；`btw`/`style-selector` 仅有构建与类型验证，未做运行时实例化。
