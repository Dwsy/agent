# 新增自定义上下文压缩扩展

为 Pi 0.80.3 增加可配置的上下文压缩模型、算法和交互式 TUI，并避免与 `role-persona-old` 竞争最终压缩结果。

## 背景与目的 (Why)

Pi 默认压缩固定使用当前会话模型。用户需要在不复制 Provider/OAuth/API-key 管理的前提下选择已认证 Pi 模型，并能选择适合编码任务的摘要算法。

## 变更内容概述 (What)

- 新增 `extensions/pi-custom-compaction/` 自动发现扩展。
- `/compaction` 提供带完整边框的 SettingsList TUI：开关、带模糊搜索的模型子菜单、算法、结构化摘要预算和状态 widget。
- 从 `ctx.modelRegistry.getAvailable()` 动态读取已认证文本模型。
- `pi-default` 调用 Pi 导出的 `compact()`；`structured` 生成编码 checkpoint。
- 配置首次加载时创建，并以随机临时文件 + 原子 rename 保存。
- 修改 `role-persona-old`：当自定义压缩拥有已认证模型时，让出最终 `CompactionResult`；同时通过 `role-persona-old.compaction-memory-handoff` 将 `<memory>` 指令、解析和持久化交给 custom 压缩链路，保留压缩时记忆提取。
- 模型搜索结果仅展示模型标识和输出价格；不再显示上下文窗口。
- status widget 默认关闭，用户可在面板中显式开启。

## 风险与影响评估

- 压缩模型实际请求会产生该模型的正常 token 成本。
- 用户未选择模型、模型认证失效或摘要失败时，扩展返回 `undefined`，由 Pi 原生压缩安全回退。
- role-persona-old 的 compaction memory extraction 在自定义 owner 有效时跳过，避免最后加载的 handler 覆盖用户选择的模型/算法；其 agent-end memory extraction 不受影响。

## 回滚方案

- 执行 `/compaction off` 即停止接管压缩。
- 删除 `extensions/pi-custom-compaction/` 后 reload Pi；`role-persona-old` 恢复自己的压缩 memory extraction。
- 如需只恢复角色侧行为，可还原 `extensions/role-persona-old/index.ts` 的 owner guard。

## 兼容性

- 依赖 Pi `0.80.3` 的公开 `session_before_compact`、`ModelRegistry`、`SettingsList` API。
- 不注册 Provider、不读取或写入 API key；认证始终由 Pi 管理。
- 角色系统 prompt 在 `before_agent_start` 注入，不会传给 compaction 的 summarization-only request。
