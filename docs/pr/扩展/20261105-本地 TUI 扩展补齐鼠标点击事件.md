# 本地 TUI 扩展补齐鼠标点击事件

> 自绘列表/菜单组件支持左键 press 选中 + click 确认，语义与 pi-tui 内置 `SelectList` / `SettingsList` 一致。

## 背景与目的 (Why)

上一轮只补了 wheel，明确暂缓 click 命中测试。用户要求补齐点击。内置组件的既定语义是 `press` 选中并请求焦点、`click` 选中并执行确认动作；自定义扩展必须沿用，否则同一会话里点击行为不一致。

## 变更内容概述 (What)

- **8 个文件、11 个自绘组件**在已有 `handleMouse` 里追加 press/click 分支，wheel 逻辑原样保留
- **统一命中手法**：`render()` 时记录 `rowMap: number[]`（下标 = 渲染行 `y`，值 = item 绝对 index，`-1` = 表头/分组头/空行），handleMouse 用 `event.y` 查表；自动与滚动窗口、分组头、表头对齐
- **两段式**：press 记录 `pressedIndex` 并选中（`{ handled: true, focus: true }`），click 用 `pressedIndex ?? index` 执行该行的键盘确认动作（`{ handled: true }`）；右键/中键/move/drag/release 返回 `undefined`
- **复用 Enter 路径**：`role-control-center` 与 `style-selector` 的 click 直接调用 `handleInput("\r")`（已验证 `matchesKey("\r", Key.enter)` / `"return"` 均为 true），避免重复副作用
- **双栏**：`tool-inspect` / `pi-mesh` 仅 `event.x < splitX` 的左栏行可点；右栏详情区返回 `undefined`
- **例外**：`pi-fzf` 的 Enter 是「保存全部并关闭」，单击某项直接保存全部不合直觉，故 click 执行 `toggleSelected()`（等价 Space）
- **wrapper 与纯文本 overlay 不改**：wrapper 上一轮已转发，内置 `SelectList`/`SettingsList`/`Input`/`Editor` 自带点击；PromptViewer、RoleMemoryViewerComponent、MarkdownOverlay 无可点控件
- **坐标修正**：`usage-extension` wrapper 在组件输出前拼了边框行，转发时改为 `y: event.y - headerRows`

## 风险与影响评估 (Risk Assessment)

| 轴 | 影响 |
|---|---|
| UX | 全屏模式左键可选中并确认；regular 模式不变；键盘与 wheel 路径不变 |
| DX | 每个组件多一个 `rowMap` 字段 + 两段式分支；无共享抽象，重复但局部、易 grep |
| Agent 可读性 | `rowMap` 与 render 逐行对齐是硬契约，已用契约测试锁定；契约测试同时断言纯文本/wrapper 不越界 |

风险点：`focus: true` 会把键盘焦点设到 overlay 组件；这些组件的 `handleInput` 内部会转发给自己的 Input，键盘输入路径未受影响（未经人工交互验证）。

## 已知限制（未在本轮修改）

上一轮把 `handleMouse` 转发给 pi-tui 内置组件的 wrapper，转发时未平移坐标，会让内置 `SelectList` / `SettingsList` 的 `event.y` 命中错误行：

| 文件 | 偏移来源 |
|---|---|
| `pi-custom-compaction/src/ui.ts`（2 处） | `Search model:` + Input + 空行；`framePanel` 的 1 行上边框 |
| `pi-rtk-optimizer/src/zellij-modal.ts` / `config-modal.ts` | `renderFrame` 的 `contentStartLine` + 左右 padding |

本轮只修了 `usage-extension`（它的 `UsageComponent` 是本轮新加 rowMap 的自绘组件，必须对齐）。这些 wrapper 需要统一的「转发时平移 y/x」契约并配合真实交互验证，建议单独一轮。
