DeepSeek Harness · Developer Preview · 2026-08-14 调研快照

模型是大脑。
Harness 是身体、神经和运行时。

DeepSeek Harness 最重要的不是“又一个 AI 编程助手”，而是它试图把 Agent 的运行环境本身做成可组合、可替换、可回放、甚至可被 Agent 临时改写的系统。

Agent=Model+Harness
核心判断：它更接近 Agent Runtime / AI System Substrate，而不是 Claude Code 的简单复刻。
结论 架构 可扩展点 四种模式 工具 自我迭代 论文 外部 UI 对比 Pi Agent 社区 它能成为什么 来源
01 · Thesis

它真正卖的不是一个 Agent，而是“造 Agent 的底盘”。

官方的关键词是 Everything is a plugin。Model、Tool、Skill、Session、Sandbox、Storage、Agent Loop、Scheduling，甚至 UI，都不是不可替换的“核心”。Cordis 负责把它们动态组合起来。

一句话结论

DeepSeek Harness 是一套 事件溯源 + 插件化运行时 + 可逆组件生命周期 的 Agent 系统骨架。它的野心比“做一个好用的 Coding CLI”更底层：让同一套 runtime 可以生成多种 Agent，并为未来的自修改、自演化留下结构化入口。

02 · Architecture

Cordis 把 Agent 拆成“可以拔插的系统”。

DeepSeek Harness 没有一个必须被魔改的 privileged core。插件通过稳定的 ctx.<key> 获取能力，通过声明依赖决定何时激活，通过 typed events 交互；注册本身被视为可撤销 effect。

03 · Extension Surface

“可扩展点”到底是什么？几乎是整个系统。

如果你说的“可可转点”是“可扩展点”，DeepSeek Harness 的答案非常激进：不是给一个 monolith 留几个 hook，而是把能力本身做成 seam。

MODEL

模型路由

在 ctx.llm 注册 adapter。DeepSeek 不是唯一模型；官方也提供多 provider 路径。

TOOLS

工具面

Tool schema、执行、pre/post policy、timeout、结果观察都在独立管线里。

SESSION

会话与持久化

事件类型、持久化后端、查询、fork/replay 都可围绕 SessionEvent 扩展。

LOOP

Agent Loop

连“模型何时请求、工具何时执行、何时停止”的 loop 都不是不可替换核心。

WORLD

执行环境

Filesystem、subprocess、shell、terminal、sandbox 可更换 provider，而工具 schema 无需跟着重写。

AGENCY

Skills / Subagents

Skills、Goals、Subagents、Jobs、Workflow 是独立能力，不被硬塞进一个 God Object。

POLICY

权限与治理

tools/pre-execute / execute / post-execute 可以挂审批、拒绝、审计与治理策略。

UI

用户界面

UI 只是订阅 Agent 和 Session 事件的客户端层；它也可以由插件贡献新的 conversation node。

04 · Presets

四种预设，说明它不是只想做一个“固定产品”。

STANDARD

标准模式

完整 coding agent：文件读写/搜索、Shell、Skills、Plan、Goal、Subagent、Workflow、Background Jobs 等。最像“成品 Coding Agent”。

PTC / CODE

程序化工具调用

能力与 Standard 基本相同，但模型主要看到 run_code 和生成的 TypeScript SDK。多次工具往返可以合并成一个程序执行，降低 round-trip。

MINIMAL

最小模式

刻意只保留两类模型工具：持久 Bash + str_replace_editor。没有完整 prompt 拼装，也没有 compaction。它像一个“研究基线”。

CREATOR / CORDIS

创造模式

Standard + 运行时检查 + 插件实验 + preset 创作指导。官方注释写得很直白：它存在，是为了“让一个 Agent 去创作另一个 Agent”。

05 · Tools

它内置的不只是文件、Shell 和搜索。

从仓库中的工具包与 Standard 组成可以看到，DeepSeek Harness 已经覆盖 Coding Agent 的完整工作面。最有辨识度的是 Creator 模式里的自指 Cordis 工具。

06 · Self Modification

它的“自我迭代”不是魔法：先把自己变成一个可回滚实验场。

目前真正落地的是 runtime self-modification 的基础设施，而不是“模型永久自主升级自己”。Creator/Cordis 模式可以在同一进程里检查、定义、运行、撤销模型写出的临时插件。

01
Inspectcordis_inspect 查看当前服务、工具、事件、动态包与 UI 插槽。
02
Define模型生成 host/browser 插件代码，Harness 先做语法与结构检查，但暂不运行。
03
Run在 live runtime 中挂载临时插件，让它贡献工具、prompt、listener 或 UI。
04
Observe通过 Session log、测试、工具结果和行为轨迹判断这次修改是否真的有益。
05
Stop / Keep失败则 stop/undefine；成功也不会自动永久化，必须再实现为正常插件/preset。
边界非常重要：动态插件只存在于进程内，默认不落盘、不跨重启；官方明确说 VM sandbox 不是安全边界，要像 Bash 权限一样谨慎授予。Cordis 也只能可靠撤销被它追踪的 effect；外部不可逆副作用仍需要事务、补偿或额外治理。
不要混淆另一篇论文：Self-Harness: Harnesses That Improve Themselves 讨论的是 Weakness Mining → Harness Proposal → Evaluation 的自动优化算法。它与 DeepSeek Harness/Cordis 不是同一个项目。二者方向相邻，但不能把前者的实验结果算到 DeepSeek Harness 头上。
07 · The Paper

为什么发一个 Harness，还要配一篇“时空可组合性”论文？

因为真正难的问题不是“插件能不能加载”，而是：当 Agent 在运行中不断加入、删除、替换自己的工具和策略时，系统能否保证自己不会被改成一团无法恢复的状态。

TEMPORAL

时间可组合性

组件被移除时，它造成的可追踪副作用应该能够被完整撤销。Cordis 将 effect 与 inverse 配对，由 runtime 记录。

SPATIAL

空间可组合性

组件声明自己依赖哪些服务。Provider 出现、消失或被替换时，相关组件自动失活/重激活，而不是手写启动顺序。

DYNAMIC

动态组合

把二者合起来，Cordis 才能做配置 reconciliation、Hot Module Replacement，以及失败时的局部恢复。

传统插件系统：load() → 希望开发者记得 cleanup() → 祈祷依赖顺序正确

Cordis：
  context transformation = effect + inverse
  dependency              = declared coeffect
  runtime                 = track + react + reconcile

结果：组件生命周期不再主要依赖“开发者记得善后”。
论文真正服务的未来：当 Agent 自己开始生成 Tool、Memory、Sandbox、Orchestration 插件时，“可撤销、可重连、不会半热更新”不再只是工程洁癖，而是自我演化系统的生存条件。

注意：Cordis 论文是 2026-08-13 的 active-revision preprint，理论与实现仍可能快速变化。

08 · External UI

外部 UI 是未来吗？更准确地说：
“UI 与 Agent Runtime 解耦”是未来。

DeepSeek 的 Web UI 不是 Agent 本身。它消费 ctx.agents 和 session/event，把同一条事实流画出来。没有 Web Server，Headless runner 仍然可以工作。

为什么这样更强

  • 同一 Agent 可同时拥有 Web、IDE、TUI、API、自动化入口。
  • 前端崩了，Agent 的持久事件日志仍然存在。
  • Replay/Fork 不依赖某一种 UI 如何存聊天消息。
  • UI 可以独立进化，不污染模型 loop。

为什么 TUI 不会消失

  • 开发者在终端里仍然追求最低交互延迟。
  • SSH、tmux、自动化环境天然适合文本界面。
  • 真正的未来不是“Web 赢”，而是 runtime 只暴露事件/命令协议，客户端自由竞争。
我的判断

DeepSeek Harness 选择外部 UI 的意义，是把 Agent 从“一个界面里的聊天机器人”升级成“一个可被多种界面驾驶的后台系统”。这比 Web UI 本身更重要。

09 · DeepSeek Harness vs Pi Agent

DeepSeek 更像“可组合 Agent OS”；Pi 更像“极简可编程终端 Harness”。

两者不是同一条审美路线。Pi 明确选择 minimal core + TypeScript extensions；DeepSeek 选择把更多系统层都结构化成 provider/seam/plugin。

维度DeepSeek HarnessPi Agent谁更占优
哲学Everything is a plugin，连 loop/session/UI 都可组合。Minimal terminal harness，核心小，能力通过 extension/skill/package 增长。看目标：系统平台选 DeepSeek；个人高效工作台选 Pi。
默认工具面Standard 已含文件、Shell、Web、Skills、Plan、Goals、Subagents、Workflow 等。默认只有 read/write/edit/bash，刻意不内置 plan/subagent。开箱自治能力：DeepSeek。
能力替换Service Definition → Provider → Consumer 的显式 capability seam。Extension API 很强，但更多是在稳定核心周围注入行为。底层 provider 替换：DeepSeek。
运行时动态性Cordis effect tracking、reactive dependencies、HMR；Creator 可临时写 runtime。Extension 可 reload，可拦截生命周期，但没有同等形式化的可逆组件模型。动态重组：DeepSeek。
会话模型Append-only SessionEvent 是模型历史与 UI 的统一 SSOT。树形 Session、branch/compaction 成熟，SDK 暴露事件流。审计/回放一致性：DeepSeek 的理念更彻底；交互工作流各有优势。
UIWeb Client 是插件，Host/Runtime 可独立运行。终端原生，但 SDK/RPC 本身也支持外部 UI/嵌入。Web/多客户端产品化：DeepSeek；终端手感：Pi。
复杂度包、Context、Service、Realm、Event、Preset、Bundle 层次很多。心智模型小，扩展一个 TS 模块就能做大量事情。Pi。
成熟度2026-08-13 刚进入 developer preview，官方承诺会有 breaking changes。已形成稳定的 terminal/SDK/RPC/extension 工作方式。当前生产稳定性：Pi 更保守。
DeepSeek 相比 Pi Agent 最实质的优势：不是“工具更多”，而是它把运行时替换、事件事实源、可逆生命周期、自指修改都上升成一等架构概念。Pi 的优势则是极小、直接、易改，不需要先理解一套动态组件理论才能加功能。

POSITIVE

大家在兴奋什么

  • 把 Agent Loop 也插件化，激进但一致。
  • 不必为了换一个 provider / sandbox 就长期维护 fork。
  • 事件日志 + replay/fork 对调试 Agent 很有吸引力。
  • Creator 模式让“Agent 创作 Agent”第一次变得很具象。
CAUTION

大家在担心什么

  • 运行时组合比 source diff 更隐形，调试插件冲突需要好工具。
  • 超高模块化会带来学习成本和配置复杂度。
  • ToolSearch / 大规模工具渐进披露仍在社区讨论中。
  • Developer preview：今天的 API 不是稳定契约。
不要把 stars 当 benchmark。目前最可信的结论是“这个架构命中了开发者兴趣”；至于长期可靠性、插件生态质量、版本兼容成本、复杂工程性能，需要数周到数月真实使用后才能判断。
11 · What It Can Become

它可以从 Harness，长成一个“AI 系统运行层”。

如果把模型看作一个可替换的 cognition module，那么 DeepSeek Harness 已经覆盖了 Agent 作为“系统”需要的大多数其它部分：状态、行动、权限、工具、环境、调度、审计和界面。

NEXT

RESEARCH

Self-Evolving Substrate

Creator + Cordis 给了“修改自身 runtime”的安全雏形；再叠加 eval/optimizer/长期记忆，才可能真正走向持续自我改进。

所以，它是不是一个 AI 系统？

它本身不是 AI 模型，但它已经是 AI 系统的运行骨架。更准确的公式是：

AI Agent System = Model + Harness + Environment + Tools + State + Policy + UI

DeepSeek Harness 正在试图拥有等号右边除 Model 之外的大部分结构，并允许 Model 反过来修改其中一部分。
