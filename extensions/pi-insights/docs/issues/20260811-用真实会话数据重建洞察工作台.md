# Issue: 用真实会话数据重建洞察工作台

## Goal

把 pi-insights 从「让模型编故事的静态报告」改造成「只呈现会话记录里确实存在的事实」的本地分析工作台：数据层读真实 JSONL，服务层提供冻结的 HTTP 契约，前端是零构建的开发者仪表盘。

## 背景/问题

原型的问题不是界面难看，而是**数字是假的**，界面只是把假数字包装得像真的：

- `session-meta.ts` 用 `Math.floor(cmd.length / 50)` 从 bash 命令字符串长度「估算」代码行数。
- `languages` 字段声明了却从未被填充，永远是空对象。
- `aggregator.ts` 消费一个恒为空的 facets map，因此 outcome 四个桶永远是 0；报告里的「Success Rate」实际是 `1 - error_rate`，与任务成败无关。
- `lite-scan.ts` 每个项目目录只取**第一个** `.jsonl`，6980 个真实会话文件里只看得到约 390 个。
- 会话记录里**真实存在**的 `usage`（token、cost、cacheRead/Write、reasoning）从头到尾没有被读取过。
- `facets.ts` 让 LLM 编造 `outcome` / `claude_helpfulness` / `friction_counts`，再把编造结果当统计量聚合。
- 报告模板是 emoji 标题（`📊 At a Glance`、`🎉 Fun Facts`）+ 灰色圆角卡片堆叠。

即：AI slop 的根源在数据层，不在样式层。只改样式等于把谎言排版得更好看。

## 验收标准 (Acceptance Criteria)

- [x] WHEN 生成任何指标，系统 SHALL 只使用会话 JSONL 中记录的事实，且 SHALL NOT 调用任何语言模型。
- [x] WHEN 扫描会话，系统 SHALL 遍历全部项目目录下的全部 `.jsonl` 文件。
- [x] WHEN 某项测量无样本，系统 SHALL 渲染 em dash 并说明原因，SHALL NOT 渲染 `0`。
- [x] WHEN 展示比率，系统 SHALL 同时给出分子与分母。
- [x] WHERE 呈现「信号」，系统 SHALL 由固定阈值规则产生，并附带触发它的实测值；每条规则 SHALL 有最小样本量护栏。
- [x] IF 视口宽度为 390px，THEN 系统 SHALL 无横向滚动且无内容截断。
- [x] 系统 SHALL 通过单元测试、静态 UI 闸门与渲染态视觉回归。

## 关键决策

| 决策 | 理由 |
|------|------|
| 删除全部 LLM 生成环节，不做「可选 AI 摘要」 | slop 的来源就是让模型对统计量编解释；保留开关等于保留退路。工具的价值在于可核验。 |
| 信号规则化 + 附实测证据 | 观察结论仍有价值，但必须可被读者当场证伪，而不是要求信任。 |
| 无样本渲染 em dash 而非 0 | `0 ms` 是「测到了，是零」；em dash 是「没测到」。混淆二者就是把缺失伪装成事实。 |
| 先写 UI 闸门再写 UI | 把「不许 emoji、不许 CDN、文案必须进 i18n」变成 CI 断言，而不是评审时的口头约定。 |
| 契约先行、三层并行 | 三个实现体同时开工需要冻结接口；`src/types.ts` + `docs/contract.md` 是唯一事实源。 |
| 活跃时长按 5 分钟空隙截断 | 墙钟时长把「开着窗口去吃饭」算成工作；两者都报，但默认展示专注时长。 |
| 视觉回归用 fixture 而非真实数据 | 断言必须确定性，且不能依赖开发者本地有多少会话。 |

## 遇到的错误

| 日期 | 错误 | 解决方案 |
|------|------|---------|
| 2026-08-11 | 关闭态详情弹窗仍覆盖右侧 560px：`.detail { display: flex }` 作者样式压过 UA 的 `[hidden] { display: none }`，且 `role="dialog" aria-modal="true"` 常驻可见 | 增加 `.detail[hidden] { display: none; }` |
| 2026-08-11 | KPI 卡片被裁掉底部 114px：`.view` 是定高 flex 列，`.metric-grid` 因 `overflow: hidden` 自动最小尺寸为 0，先于容器滚动被压缩 | `.view > * { flex-shrink: 0; }` |
| 2026-08-11 | 数据层与服务层相对导入扩展名不一致（`.ts` vs `.js`） | 统一为 `.js`，与 pi-provider-trace 既有约定一致 |
| 2026-08-11 | 会话详情摘要 `.detail-facts` 完全不可见：与 `.metric-grid` 同一成因，在 `.detail-body` 这个定高 flex 列里被压缩为 0 | `.detail-body > * { flex-shrink: 0; }`；同时把这类塌陷检查推广到视觉回归脚本的两个滚动容器 |
| 2026-08-11 | 时间线里 `error` / `interrupt` 行的 label 就是 `"error"` / `"aborted"`，与 kind 重复，纯噪声 | 改为携带当次的 `provider/model`——扫一串失败时真正想知道的是哪个模型在失败 |
| 2026-08-11 | 模型/工具/项目三张表根本不可排序，只有会话表能排 | 把排序访问器下沉到 `state.js` 的 `SORTERS`，四张表统一走 `sortView`；无测量值的行在两个方向都沉底，不伪装成 0 |
| 2026-08-11 | 占比/错误率条形按 0–100% 绘制，实际数据挤在低区间，所有行看起来一样长 | 按列内最大值缩放，并在表头写明「条形满格 = X%」；最大值本身接近满格时退回 0–100%，避免多余说明 |
| 2026-08-11 | 详情摘要用 gap-as-background 画分隔线，10 个字段除不尽响应式列数，末行空轨道被染色成「坏掉的格子」 | 分隔线改画在单元格上并用负 margin 越过裁剪边界 |
