# pi-mesh 设计

> 决策记录写「选了什么 / 否决了什么 / 为什么」。已被否决的方案不要在没有新证据时重提。

## 1. 设计原则

1. **能力面零 tool**：不往任何 pi 里塞工具。模型通过 skill 知道 mesh 存在，通过
   `mesh` CLI 执行。
2. **人是发起者**：hub 被动。只有用户显式触发才 spawn 进程（resume / 新建对话 / 终端）。
3. **身份连续**：恢复会话是「同一条会话活过来」，不是新建一条。
4. **状态只影响语义，不影响位置**：排序永远不跟心跳走。
5. **工作台，不是仪表盘**：两栏、行列表、常驻详情；拒绝卡片流与模态抽屉。
6. **删除优于新增**：能靠结构表达的，不靠标签、说明文字、装饰动效。

## 2. 能力面：为什么零 tool

```text
每个 pi 都装 pi-mesh
  ├─ 若注册 tool：每个会话的工具表都多 N 项，模型每轮都要读
  └─ 实际选择：resources_discover → skillPaths
       system prompt 只多 name + description
       模型需要时再读 SKILL.md，执行走 bash + mesh CLI
```

- 先例：generative-ui、pi-session-bridge 都是纯 skill 驱动。
- `/mesh` 是给人看的 TUI 面板，不进模型上下文。
- CLI 默认 JSON（可 `jq`），`--table` 才是人类视图；会话 id 接受任意唯一前缀。

## 3. 协作模型

### 3.1 关注图

```text
A.following = [B]       有向边，存在 A 的记录上
B 状态变化 ──► 只推给关注 B 的会话
发消息成功 ──► 自动补 A → B 的边（unfollow 显式解除）
```

- 通知以「隐藏消息 + toast」落入接收方会话，`triggerTurn: false`——协作，不打断。
- hub 侧同时发 `herdr notification`，只在存在关注者时发，只带身份信息。

### 3.2 互发与取消

- `steer`：在对方下一次模型调用前插队，用于紧急纠偏。
- `followUp`：对方当前回合结束后排队，用于非紧急请求。
- `cancel`：等价于在对方会话里按 Esc。
- 目标离线/已关闭 → 直接拒绝，不排队、不假装成功。
- WebUI 只允许向 **running / waiting** 目标发送；waiting 表示在线空闲，离线/已关闭时禁用发送并保留草稿。
- 每个目标会话独立保存草稿；发送时冻结目标、正文、模式与协作来源。只有目标扩展明确接受且草稿版本未变化时才清空；明确拒绝和传输结果不确定都保留草稿，不自动重发。
- Enter 在 IME composition 期间只提交候选字，不触发发送；同一目标同时只允许一个发送请求。
- **fromSessionId** 是协作来源，不代表冒充该会话发言。指定来源时，成功投递会建立来源 → 目标的关注边；网页直发不建立关注边。来源选择保留用户已有选择，只有原会话记录消失时才回退到第一个在线会话；无在线来源时保持网页直发。
- UI 只把 handled / queued / started 统一描述为「已交给目标扩展」，不把扩展接收误报为模型已处理；超时或网络中断显示「发送结果未确认」，提示先检查目标，不自动重试。

### 3.3 恢复（resume）

- 默认 `pi --session <file>`：续写同一 JSONL，身份连续。
- `--fork`：新会话，逃生舱。
- 双开由 hub 的 CAS 租约互斥（60s TTL），跨 CLI / TUI / WebUI 三个表面统一。
- 工作区名 `pi-<tail8>` 确定性生成，存在即复用，避免工作区堆积。
- 人类触发聚焦；agent 触发（`PI_SESSION_ID` 存在）默认 `--no-focus`。

### 3.4 终端

- WebUI 内嵌 wterm（libghostty WASM），经 hub 桥接 `herdr terminal session`。
- `control` 可键入；`observe` 只读镜像。
- 触屏默认「鼠标·本地」，终端是桌面优先能力，移动端给受限提示而不是假装完整。

## 4. 产品形态：Session Workbench

### 4.1 桌面（≥1180px）

```text
┌────────────────────────────────────────────────────────────┐
│ TopBar 44px  pi-mesh  [⌘K 搜索/命令]  协作来源▾  SSE●  ☾  ⟳ │
├──────────────────────────────────────┬─────────────────────┤
│ SessionList（默认 480，360–720）      │ DetailPane（剩余）  │
│ [全部] [在线] [离线] [已关闭]         │ 会话  变更  终端     │
│ 搜索 [⌘K]                            │ 内容（滚动）         │
│ ▾ repo · N                           │─────────────────────│
│    branch · N                        │ Composer 常驻        │
│    40px 行 + 选中条                  │                     │
└──────────────────────────────────────┴─────────────────────┘
```

- 左栏已并入列表：状态过滤在列表头一行，分组分两层——repo 头可折叠，
  分支头是静态标签；过滤是分组头右侧的独立图标，不抢主点击。
  不同路径下同名 repo 只在冲突时显示父目录段（`20261031/1`）。
- 顶栏左区跟随列表分隔线，形成连续的原生导航面；命令入口带明确文字，区别于列表内的可编辑搜索。状态过滤合并为中性分段控件，来源菜单不常驻显示 sessionId；连接颜色只落在状态点上。视觉细节以 `style.md` 为准。
- 列表默认 480px（1440 下约 33%，1180 下约 41%），详情吃掉剩余空间且 ≥600px。
- 断点：900–1179 → 列表全宽 + 详情右侧浮层；<900 → 单列；390 → 底部 tab
  （会话/发现/设置）+ 全屏推入详情。
- 状态过滤只有「全部 / 在线 / 离线 / 已关闭」四项；在线包含运行中与在线空闲。首次访问默认在线，旧版运行中/等待过滤值迁移为在线；用户选择持久化，有搜索词时跨状态匹配，不能让离线历史会话被在线过滤藏起来。
- 状态只改变筛选与可操作性，不改变行排序；列表始终按 startedAt + sessionId 稳定排序，不按心跳或状态跳动。
- 行级只保留 3 个高频动作：发消息、终端、⋯（其余进 overflow）；桌面默认隐藏，
  hover / 选中 / 键盘 focus 时出现。
- 详情 3 个 tab：会话 / 变更 / 终端；文件活动作为会话视图的轻入口，文件树并入 Review（点文件跳到 diff）。
- 详情宽度跨 tab 恒定，切换不跳动。
- 只有列表侧一个拖拽把手：1px 发丝把手 + 5–6px 热区，列表 clamp 360–720 且
  详情 ≥600；写入 `pi-mesh.panes` 时只存 `list`，双击复位 480。

### 4.2 交互模型

- 键盘：↑↓ 选行、Enter 进详情、1–3 切 tab、/ 搜索、⌘K 命令面板、
  f 关注、R 恢复、e 进入 herdr、Esc 逐层退出。
- 选择持久化：`pi-mesh.selected` + URL hash `#p=<sid>&tab=<t>`；SSE 刷新不动选择。
- 分组折叠：点 repo 头折叠/展开，状态存 `pi-mesh.collapsed`；搜索时强制展开、
  清空恢复；折叠组不渲染行，键盘顺序同步跳过。
- 搜索/过滤无结果必须有空态；加载有骨架；错误不整块红底。
- 选择持久化：selectedId + URL hash 中的 sessionId / tab；变更视图额外带 canonical file key，支持精确文件深链接、刷新恢复与切回变更视图时恢复选中项；SSE 刷新不动选择。
- 状态过滤持久化在 pi-mesh.state-filter；首次默认 online。搜索覆盖状态过滤但不改写已保存的过滤选择；当前详情目标被过滤隐藏时保留详情与草稿，并提供「定位会话」恢复可见。
- Composer 始终显示目标状态与协作来源。来源文案说明是否会建立关注边；来源离线仍保留显式选择并标明状态，不静默改成另一个来源。
- 短暂的空 SSE peers 快照不清除已选目标或协作来源；只有后续非空快照确认原会话已不存在时，才重新选择在线来源。
- 一次性只允许一个菜单实例（行 ⋯ 与右键共享状态是曾经的 P1 bug）。

### 4.3 TUI 面板（`/mesh`）

同一套信息架构的终端版本：

```text
╭ pi-mesh · 活跃 12 · 关闭 25          a 过滤  / 搜索  ? 帮助 ╮
│▾ AI/agentdock / main · 2                                  │
│  ❯▶ 5bedf83c  2h  修复 file_edit…            3f  ↻1  ◆   │
│   · 0ebfd227  3h  pi-new-vw5xfn                           │
│▸ 已关闭 · 25                                              │
╰ ↑↓ 移动 · Enter 详情 · f 关注 · R 恢复 · r 刷新 · q 关闭 ╯
```

- 默认只看活跃会话；已关闭折叠成一行，需要时展开。
- `a` 循环 活跃/全部/关闭；`/` 搜索；`?` 帮助；宽屏两栏，窄屏推入详情。
- 分组按组内最佳状态排序（running → waiting → offline → closed），首屏落在活跃会话；
  自身会话带 `本` 标记。
- 年龄用 `startedAt` / `closedAt`，不显示心跳时间。
- 选中按 sessionId 跟踪；列表有真实 scroll offset；面板高度跟内容收缩（裁掉尾部空行），
  内容多时才撑满并可滚动。

## 5. 决策记录

| # | 决策 | 否决的方案 | 理由 |
| --- | --- | --- | --- |
| 1 | 零 tool，skill + CLI | 注册 `mesh_*` 工具 | 工具表膨胀；skill 已能渐进披露 |
| 2 | hub 被动，CLI 编排 resume | 扩展自己 spawn；hub spawn | 扩展无法启动它所在的 pi；hub 保持无进程 |
| 3 | 恢复同一记录（revive） | 每次新建/fork | 身份连续是「恢复」的本义；fork 保留为 flag |
| 4 | hub CAS 租约互斥 | `flock`；paneId 链接 | 三个表面统一互斥；两套锁违反 KISS |
| 5 | 运行时自报 `isPersisted()` | argv 嗅探 `--no-session` | `-n` 是 `--name`，argv 会误判；运行时才知道真相 |
| 6 | 按 `startedAt` 排序 | 按 `lastHeartbeat` | 每 peer 心跳时刻不同，列表会 15s 抖一次 |
| 7 | wterm + herdr 终端桥 | 自建 PTY；内嵌 xterm | herdr 已有 pane 与重放；浏览器只需要终端前端 |
| 8 | Review 独立模块 | 塞进 `app.js` | 542 行领域逻辑 + 独立 sanitizer 边界 |
| 9 | 前端资源本地 vendor | 外链 CDN | 代理/断网时 CDN 失败会整页白屏（实测撞过） |
| 10 | 无构建 WebUI | Vite/React 重写 | 单页工具，import map + Alpine 足够；零构建降低维护面 |
| 11 | 表单控件全自定义 | 原生 `<select>`/checkbox | 原生铬件与 native 外壳冲突；保留真 input 保 IME/a11y |
| 12 | 图标只用 Lucide | emoji / 字形速记 | 跨平台渲染不一致；emoji 当图标是 slop 信号 |
| 13 | 只保留 fade 动效 | scale/bounce/pulse/shimmer | 原生工具感；装饰动效不提供信息 |
| 14 | 删除冗余标签 | 加说明文字/副标题 | 「让代码自己解释」；标签是结构没做好的补丁 |
| 15 | TUI 过滤 + 折叠 + 真滚动 | 平铺全部会话 | 25 个 closed 会淹没活跃会话；假滚动比没有更糟 |
| 16 | 左栏并入列表（两栏） | 保留三栏 GroupRail | 左栏只重复列表已有的分组；两栏把宽度还给会话与详情，过滤入口移入列表头与分组头 |
| 17 | 在线过滤合并 running/waiting，四个状态筛选 | 运行中/等待拆成两个入口 | 用户首先需要判断是否可协作；运行与空闲是在线状态的次级区别 |
| 18 | Composer 按目标隔离草稿、冻结请求快照、区分拒绝/未知 | 全局共享草稿；超时自动重发；成功即清空当前文本 | 避免切会话串稿、重复投递和异步回执覆盖新输入；HTTP 成功不等于模型已处理 |
| 19 | Review 文件身份用 canonical file key，URL 记录文件选择 | 用展示路径或 basename 做身份 | monorepo 同名文件必须保持区分；绝对/相对别名可合并，深链接刷新后仍定位同一文件 |

## 6. 非目标

- **SSH 跨机 mesh**：协议已按 `machineId` 预留，但 Phase 5 之前不做。
- **自动 resume**：恢复必须是人的决定。
- **文件系统 watcher**：只认 `edit` / `write` 工具调用。
- **多用户 / 鉴权**：单机单用户，绑定 127.0.0.1 是边界。
- **TUI 发消息 / 鼠标**：当前 TUI 只做导航、历史、关注、恢复。

## 7. 已知取舍与待裁决

| 项 | 状态 |
| --- | --- |
| 历史消息块是卡片式（8px 圆角 + 边框 + 微阴影） | 擦「无卡片汤」的边，作为消息线程可接受；用户未裁决 |
| 临时会话仍显示 历史/Review tab（打开是空态） | 非阻塞 nit；隐藏 tab 更干净 |
| 终端交互（点击/滚轮）多次被 UI 大改踩坏 | 已修复 3 次；需要静态回归契约，避免第四次 |
| `disposition` 恒为 `started` | 排队语义由 pi 的 `deliverAs` 决定，mesh 不自造队列 |

## 8. 验收方式

```text
功能      bun test 全绿——任何改动的前置门槛
视觉      真实浏览器（CDP）+ 1440 / 900 / 390 三视口截图
硬规      渲染后 DOM 扫描：emoji 0 · 原生 select 0 · slop 0 · 对比度 ≥4.5
交互      键盘旅程 + 拖拽 + 终端真实输入（点击/滚轮/历史）
循环      blocker → 返工 → 复验；判定追加进 docs/ux-verify/VERDICT.md
```

只跑单测不算完成：UI 变更必须有真实视口证据，终端变更必须有真实 pane 输入证据。
WebUI 交付还要覆盖：IME Enter、每目标发送锁、目标/来源快照、草稿版本保护、明确拒绝与不确定回执、在线/离线状态切换、筛选隐藏目标、Review 文件深链接，以及 390px 无横向溢出。
